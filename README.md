# 業績管理アプリ

論文・学会発表・講義などの業績を登録し、**業績目録**として出力する Web アプリです。

- ビルド不要の静的サイト（HTML + CSS + バニラ JavaScript、外部依存ゼロ）
- データはブラウザ内（localStorage）に保存され、外部に送信されません
- 共著者・所属・ジャーナル名とその略称を**自動で記憶**し、次回以降は候補から選べます
- JSON バックアップによりアプリを更新しても入力内容を引き継げます

## 画面構成

| タブ | 内容 |
|---|---|
| 業績の入力 | 区分に応じて入力項目が切り替わるフォーム。入力しながら出力プレビューを確認できます |
| 業績一覧 | 登録済み業績の検索・並べ替え・編集・複製・削除 |
| 業績リスト出力 | 区分を選んで業績目録を生成し、HTML / Markdown / テキスト / CSV / BibTeX / RIS / 科研費様式で出力 |
| 年度別集計 | 年度（4月〜翌3月）または暦年での件数推移と区分別内訳 |
| マスタ管理 | 記憶した共著者・所属・ジャーナル・大会名の編集と削除 |
| データ入出力 | JSON バックアップの保存と読み込み、登録状況の確認 |

## 業績区分と入力項目

区分を選ぶと、それに応じた入力欄だけが表示されます。

### 論文（学術雑誌等に発表した論文［査読有 / 査読無］）

- 共著者とその所属
- 論文タイトル
- ジャーナル名 / ジャーナル名の略称
- 発表年月日
- 巻（創刊号）・号
- ページ番号もしくは文献番号
- 査読の有無
- DOI（任意。**DOI から書誌情報を自動取得**できます）

### 学会発表（国内／国際 × 口頭／ポスター）

- 共著者とその所属
- 大会名
- 発表日
- 発表番号
- 会場（任意）

### その他（シンポジウム・講義・実習・受賞・競争的資金など）

- 共著者とその所属
- 件名・タイトル
- 名称（講義名・事業名など）／会場
- 日付
- 備考（担当内容・回数など）

## DOI から書誌情報を自動取得（CrossRef）

論文タブの「**DOI から書誌情報を取得**」に DOI を入力して実行すると、
[CrossRef REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) から書誌情報を取得し、
次の項目が自動で入力されます。

- 論文タイトル
- ジャーナル名 / 略称（`container-title` / `short-container-title`）
- 発行年月日（`published-print` → `published-online` → `issued` の順に採用）
- 巻・号・ページ（ページが無い論文は `article-number` を使用）
- DOI
- 著者（「姓, 名」の形式。チェックを外せば既存の著者を保持します）

入力形式は次のいずれでも受け付けます。取得後は通常どおり手直しでき、著者やジャーナルはマスタにも記憶されます。

```
10.1038/s41598-024-74596-x
https://doi.org/10.1038/s41598-024-74596-x
doi:10.1038/s41598-024-74596-x
```

DOI が未登録の場合や通信に失敗した場合は、原因がわかるメッセージを表示します。

## 記憶される情報

一度入力した次の情報は自動でマスタに登録され、以降は入力欄の候補（プルダウン）に表示されます。

| 種類 | 記憶される内容 |
|---|---|
| 共著者 | 氏名・英語表記・既定の所属 |
| 所属 | 名称・略称（出力時は略称を優先） |
| ジャーナル | 名称・略称 |
| 大会・講義名 | 名称 |

- 同じ名称は重複登録されません。後から略称だけを入力した場合は既存項目に補完されます。
- 共著者の氏名を確定すると、その人の**既定の所属が自動で入ります**。
- 「マスタ管理」タブで各項目を編集・削除できます。業績で使用中の項目は誤削除を防ぐため削除できず、使用件数が表示されます。

## 自分の氏名の強調

「マスタ管理」タブの**自分の氏名表記**に登録した名前は、出力時に**太字＋下線**になります。
和文名・英文名・別表記を改行区切りで複数登録でき、空白の有無は無視して判定します。

```
儀武滉大
儀武 滉大
Gibu, K.
Kodai Gibu
```

## 出力形式

| 形式 | 用途 |
|---|---|
| HTML | Word に貼り付けると太字・下線・斜体がそのまま反映されます |
| Markdown | GitHub や文書管理システム向け |
| テキスト | プレーンテキストが必要な申請書類向け |
| CSV | Excel で集計・並べ替えする場合（UTF-8 BOM 付き） |
| **BibTeX** | Zotero・EndNote・LaTeX 向け（`.bib`） |
| **RIS** | Zotero・EndNote・Mendeley 向け（`.ris`） |
| **科研費様式** | 科研費の研究発表欄に貼り付けられる書式（`.txt`） |
| 印刷 / PDF | ブラウザの印刷機能で PDF として保存 |

「プレビューをコピー」は**書式付き**でクリップボードに入るため、Word へ直接貼り付けられます。

出力例（Markdown）:

```
## 学術雑誌等に発表した論文［査読有］

- **<u>儀武滉大</u>**・井口亮 (2024). Polyamine impact.... _Scientific Reports_, 14(1), 23465.

## 国内学会等における発表［口頭発表］

- **<u>儀武滉大（東京大・産総研）</u>**・井口亮（産総研）.「南西諸島における造礁サンゴの細菌叢解析」. 日本生態学会第72回全国大会. 2025年3月15日. 発表番号I01-01.
```

### BibTeX / RIS（文献管理ソフト連携）

Zotero・EndNote・Mendeley へそのまま読み込める形式で出力します。

- **BibTeX**: 論文は `@article`、学会発表は `@inproceedings`、その他は `@misc`。
  引用キーは「著者姓＋年＋タイトル先頭語」で、BibTeX で扱いやすいよう **ASCII** に揃えます
  （英語表記が未登録で日本語しかない場合は `item2025` のような連番キーになります）。
  ジャーナル略称は `shortjournal`、区分は `keywords` に入ります。
- **RIS**: `TY`（JOUR / CPAPER / GEN）、`AU`、`TI`、`JO` / `J2`、`VL` / `IS`、`SP` / `EP`、`DO`、`UR` を出力。
  ページが「60-65」のような範囲なら `SP` と `EP` に自動分割します。

Zotero への取り込みは「ファイル → 読み込み」からファイルを選ぶだけです。

### 科研費様式

科研費の**研究発表欄**に沿った体裁のテキストを出力します。

- 〔雑誌論文〕: 著者名／論文標題／雑誌名・巻号・発行年・頁／DOI・査読の有無・国際共著・オープンアクセス
- 〔学会発表〕: 発表者名／発表標題／学会等名・発表年／国際学会・招待講演の別
- 〔その他〕: 講義・シンポジウム等

区分から自動判定される項目は次のとおりです。

| 項目 | 判定基準 |
|---|---|
| 査読の有無 | 論文区分の［査読有］／［査読無］ |
| 国際学会・国際共著 | 「国際学会における発表」区分なら「該当する」 |
| 招待講演 | 「シンポジウム・ワークショップ・招待・依頼講演等」区分なら「該当する」 |
| オープンアクセス | DOI が登録されていれば記載 |

## 年度別集計

「年度別集計」タブで、件数の推移と区分別の内訳を確認できます。

- **年度（4月〜翌3月）** と **暦年（1月〜12月）** を切り替え可能
  （例: 2025年3月の発表は年度集計では **2024年度** に入ります）
- 月が未入力の業績は、その年の年度として扱います
- 年が未入力の業績は集計対象外とし、その件数を表示します
- 年度ごとの棒グラフ、区分別クロス集計表、合計行を表示
- 集計表は CSV で出力でき、そのまま報告書に使えます

## アプリ更新時のデータ引き継ぎ

1. 更新前に「データ入出力」タブ →「**JSONファイルに保存**」でバックアップを取得
2. アプリを更新（再デプロイ）
3. 「**JSONファイルを読み込む**」で復元

読み込み方法は2種類あります。

- **既存データに追加（重複は除外）**: 別の端末で入力した分を統合する場合。マスタは名称でまとめられ、同一内容の業績は二重登録されません
- **すべて置き換える**: バックアップから完全復元する場合

データ構造にはスキーマ版数を持たせており、将来項目が増えても `migrate()` が欠けた項目を補完するため、古いバックアップもそのまま読み込めます。

## ローカルでの確認

ES Modules を使うため、`file://` で直接開かずローカルサーバー経由で開いてください。

```bash
npm run dev            # npx serve .  → http://localhost:3000
# または
python -m http.server 8000
```

テスト（Node.js 18 以上）:

```bash
npm test
```

## GitHub → Vercel へのデプロイ

```bash
cd achievement-manager
git init
git add .
git commit -m "feat: 業績管理アプリ"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/achievement-manager.git
git push -u origin main
```

1. [vercel.com](https://vercel.com) にログイン → **Add New… → Project**
2. 対象リポジトリを **Import**
3. Framework Preset は **Other**（`vercel.json` によりビルドは実行されません）
4. Root Directory はリポジトリ直下のまま → **Deploy**

## 検証済み項目（`npm test` / 全56件）

- 区分と入力形式（論文 / 学会 / その他）の対応
- マスタの重複登録防止、略称の後追い補完、使用件数の計上、使用中項目の削除防止
- 自分の氏名判定（空白の有無を無視）と太字＋下線の付与
- 論文・学会・その他それぞれの出力文字列が業績目録の書式と一致すること
- 英語表記のみの著者はカンマ区切りになること、DOI の付与
- 区分ごとのグループ化と日付順の並べ替え
- HTML / Markdown / テキスト / CSV 出力の構造、カンマを含む値のクォート
- JSON の書き出しと読み込み（置き換え / マージ）、重複業績の除外、参照の引き継ぎ
- 旧スキーマ・不正データの移行処理
- DOI の正規化（URL 形式・`doi:` 接頭辞・不正入力の判別）
- CrossRef 応答の変換（`article-number` での代替、`issued` へのフォールバック）
- CrossRef 通信の異常系（404 / HTTP エラー / 通信失敗 / 不正応答）と polite pool のクエリ
- BibTeX の種別・ASCII 引用キー・重複回避・特殊文字のエスケープ
- RIS の種別タグとページ範囲の `SP`/`EP` 分割
- 科研費様式の区分振り分けと査読・国際学会・招待講演の判定
- 年度の判定（3月は前年度）、年度／暦年の切り替え、年未入力の除外、集計 CSV の合計行

## 追加で実装している機能

ご要望の項目に加え、実務で役立つものを組み込んでいます。

| 機能 | 内容 |
|---|---|
| 入力中プレビュー | 入力しながら業績目録での見え方をその場で確認できます |
| 著者の並べ替え | ↑↓ ボタンで著者順を入れ替え。自分の行には「自分」バッジが付きます |
| 「自分を先頭に追加」 | ワンクリックで筆頭著者に自分を挿入 |
| 業績の複製 | 同じ大会の別発表など、似た内容を素早く登録 |
| 検索・絞り込み | タイトル・著者・雑誌名・大会名を横断検索 |
| 区分別の出力選択 | 申請書類に応じて必要な区分だけを出力 |
| 使用件数の表示 | マスタ項目が何件の業績で使われているかを確認 |
| 自動保存 | 登録・編集のたびに保存され、保存時刻がヘッダーに表示されます |

### 今後の拡張候補

- **ORCID / researchmap 連携**: 業績データの一括取り込み・書き出し
- **DOI の一括取り込み**: DOI を複数行貼り付けてまとめて登録
- **被引用数の取得**: CrossRef の `is-referenced-by-count` を用いた引用状況の表示
- **共著者ネットワーク**: 共著関係の可視化
- **researchmap 形式の CSV 出力**: 他システムへの登録作業の省力化
